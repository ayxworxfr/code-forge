# 模板功能与编写指南

本文档介绍 CodeForge 的模板能力、模板变量、过滤器、最佳实践以及如何编写和维护高质量模板。

## 1. 模板功能总览

CodeForge 基于 Nunjucks 模板引擎，支持以下能力：

- 数据源模式：读取 MySQL 表结构后生成代码
- DDL 模式：直接粘贴 DDL（支持多张表）后生成代码
- 模板组管理：内置模板 + 自定义模板组
- 单文件预览：按“表 + 模板文件”实时预览输出代码
- 批量生成：按已选表与模板组打包 ZIP
- 在线编辑：支持模板内容、文件名、输出路径在线修改

当前内置模板组：

1. Spring Boot + MyBatis Plus
2. Spring Boot + JPA
3. TypeScript Frontend
4. Go + Gin + GORM (DDD)

## 2. 模板渲染上下文（可直接用的变量）

模板渲染时可使用两个主对象：`global`、`table`（另外 `config` 也可用）。

### 2.1 `global` 变量

- `global.author` 作者
- `global.date` 日期（如 `2026-04-01`）
- `global.packageName` 包名（如 `com.example.demo`）
- `global.packagePath` 包路径（如 `com/example/demo`）
- `global.moduleName` 模块名（如 `system`）

### 2.2 `table` 变量

- `table.tableName` 原始表名（如 `sys_user`）
- `table.tableComment` 表注释
- `table.shortClassName` 去前缀后大驼峰名（如 `User`）
- `table.shortCamelName` 去前缀后小驼峰名（如 `user`）
- `table.entityName` 同 `shortClassName`
- `table.pkColumn` 主键列对象
- `table.primaryKey` 同 `pkColumn`
- `table.columns` 全部列
- `table.normalColumns` 非主键列
- `table.javaImports` Java 额外 import 列表

### 2.3 列对象字段（`table.columns` 每一项）

- `columnName` 列名
- `dataType` 基础类型（如 `varchar`）
- `columnType` 完整类型（如 `varchar(64)`）
- `columnComment` 列注释
- `isPrimaryKey` 是否主键
- `isNullable` 是否可空
- `isAutoIncrement` 是否自增
- `columnLength` 长度
- `defaultValue` 默认值
- `javaField` Java 字段名（驼峰）
- `tsField` TS 字段名（驼峰）
- `javaType` Java 类型
- `tsType` TS 类型
- `jdbcType` JDBC 类型

## 3. 可用过滤器（Filters）

模板中可直接使用这些过滤器：

- `camelCase`：`user_name -> userName`
- `pascalCase`：`user_name -> UserName`
- `snakeCase`：`userName -> user_name`
- `kebabCase`：`userName -> user-name`
- `constantCase`：`userName -> USER_NAME`
- `removePrefix(prefix)`：移除指定前缀

示例：

```njk
{{ table.tableName | removePrefix("sys_") | pascalCase }}
```

## 4. 模板文件组成建议

一个可维护的模板组，建议每个文件职责单一。以 Go（Gin + GORM + DDD）为例：

- `model.go`：领域实体（`internal/domain/.../entity`）
- `dto.go`：请求/响应 DTO（`internal/application/.../dto`）
- `repository.go`：仓储接口与实现（`internal/infrastructure/persistence/...`）
- `service.go`：应用服务（`internal/application/.../service`）
- `handler.go`：HTTP 处理器（`internal/interfaces/http/...`）
- `router.go`：路由注册（`internal/interfaces/http/...`）

---

## 5. 如何新建模板文件

在“模板管理 -> 编辑模板组”中点击“新增模板文件”，核心字段如下：

- 文件名：如 `handler.go.njk`
- 输出路径：生成后落盘路径（支持模板变量）
- 语言：用于编辑器高亮
- 模板内容：Nunjucks 模板正文

输出路径示例：

```text
internal/interfaces/http/{{ global.moduleName }}/{{ table.shortCamelName }}_handler.go
```

## 6. 模板编写示例

### 6.1 简单字段循环

```njk
type {{ table.shortClassName }} struct {
{%- for col in table.columns %}
    {{ col.columnName | pascalCase }} string `json:"{{ col.columnName | camelCase }}"`
{%- endfor %}
}
```

### 6.2 按条件生成（主键/非主键）

```njk
{%- for col in table.columns %}
{%- if col.isPrimaryKey %}
// 主键: {{ col.columnName }}
{%- endif %}
{%- endfor %}
```

### 6.3 输出路径模板

```text
src/main/java/{{ global.packagePath }}/repository/{{ table.shortClassName }}Repository.java
```

## 7. 常见问题与避坑

### 7.1 React/TSX 双大括号冲突

如果模板里要输出 React 对象字面量（如 `style={{ ... }}`），会和 Nunjucks `{{ }}` 冲突。  
需要使用 `raw` 包裹：

```njk
<div style={% raw %}{{ marginBottom: 16 }}{% endraw %}></div>
```

### 7.2 输出路径变量不一致

建议统一使用当前上下文字段：

- 推荐：`{{ global.packagePath }}`、`{{ table.shortClassName }}`
- 避免使用上下文里不存在的旧变量名

### 7.3 DDL 多表场景

DDL 模式已支持多表。生成时会严格按“已勾选表名”匹配，不存在的表会报错，避免误生成。

### 7.4 内置模板不可直接修改

内置模板组只读。需要先复制模板组，再进行二次定制。

## 8. 推荐模板设计规范

建议遵循以下规范，提升团队协作和模板可维护性：

1. 文件命名清晰：`*_service.go`、`*_handler.go`
2. 目录分层稳定：domain / application / infrastructure / interfaces
3. 注释统一：保留作者、日期、业务语义
4. 逻辑前置：复杂判断尽量在模板中显式表达
5. 小步预览：每改一处先预览单文件，再生成 ZIP

---

## 9. 调试建议

当模板报错时，优先检查：

1. 语法错误（未闭合标签、未闭合 `{{`）
2. 引用了不存在的变量
3. React/TSX 双大括号未 `raw`
4. 输出路径包含非法字符

建议流程：

1. 先用“代码预览”定位到具体文件  
2. 修复后再次预览  
3. 确认无误再下载 ZIP

---

## 10. 后续扩展建议

如需继续增强模板能力，建议优先级：

1. 模板语法校验按钮（保存前预检查）
2. 模板变量自动补全/说明面板
3. 模板组导入导出（JSON）
4. 多语言模板官方预设（Go/Node/.NET）
